# 项目架构

应用使用一个 Android 模块 `:app`。`MainActivity` 管理 Android 应用入口，Compose UI、导航与主题放在 `com.elainalisten.ui`。Android 字符串资源提供页面标题、操作标签和状态说明。页面选中状态来自导航栈，系统返回与页面返回使用同一导航栈。

## 语音合成

朗读和试听共用语音路由。Matcha 从 APK 资产加载原项目的中文 ONNX 模型，使用 Sherpa-ONNX CPU 推理，生成 22.05 kHz 单声道 PCM。Azure 路径使用 Microsoft Azure Speech 的晓晓或云希。文本按用户设置的 80～200 字上限分段。旧 Kokoro 音色恢复为晓晓。应用用 Android Keystore 生成 AES-256 密钥，通过 AES-GCM 加密 Speech 凭据，保存到禁用备份的应用私有存储。保存表单在本地工作。云端合成使用指定区域 HTTPS 端点及 SSML，将返回的 24 kHz 单声道 PCM 交给现有音频管线。播放器最多预生成下一段，暂停时停止发起新请求。[Microsoft Speech REST API](https://learn.microsoft.com/zh-cn/azure/ai-services/speech-service/rest-text-to-speech)

播放器保持原先的分段编号，在每段内按句合成并记录各句的 PCM 起点。阅读页用 Media3 的当前媒体项及偏移定位原文字符范围。Azure 缓存在请求和凭据加载前查找，缓存键包含音色、段长和实际合成输入的 SHA-256。未命中的句子单独请求，命中的句子直接重用 PCM。默认上限为 200 MB，按最近访问时间淘汰。清理涵盖应用私有的 Azure 音频、写入中断的缓存临时文件和旧进程的会话 WAV。

## 网页与正文

应用进程管理最多五个 WebView 标签。每个标签保留独立的导航状态和地址稿，关闭时释放 WebView。地址与操作栏的收起状态保存在本机。朗读的自动翻页绑定原标签。地址栏接受 HTTPS 或可补全为 HTTPS 的域名。WebView 拒绝非 HTTPS 导航、取消错误证书的请求，并关闭文件访问、内容提供者访问、第三方 Cookie 和混合内容。网页使用系统 WebView 的 JavaScript 兼容能力，应用不暴露 JavaScript 桥。

用户触发提取时，应用从当前已完成加载的页面读取有长度上限的 DOM 快照。Jsoup 在本地去除噪声，参照 Readability 的段落评分及链接密度思路选择正文容器，再将标题、章节与段落交给正文预览。跨页面的迟到结果会被丢弃。无法识别的网页可通过系统选词或粘贴输入。应用不建立独立浏览历史。[Readability 实现](https://github.com/mozilla/readability/blob/main/Readability.js)

Pixiv 小说优先读取当前页面作品 ID 对应的预载全文，再按需通过当前 WebView 的同源会话请求作品数据。作品页标记转成段落，显式章节保留。全文取得后作为一个作品保存。全文失败时需用户明确选择当前页预览，页面标记内容不完整。[Pixiv 小说格式](https://www.pixiv.help/hc/en-us/articles/235584168-What-are-the-special-tags-I-can-use-in-a-novel-s-body-text)

## 阅读播放

播放器依据 Compose 窗口的可用高度决定是否固定底部控制区，控制区与正文工具分别布局。应用壳将系统栏与挖孔的窗口边距合并，顶部工具栏、底部导航及内容各自使用对应边距。较窄屏幕或较大的字体下，收藏和听单按钮改为上下排列。

底栏在首页、浏览器和播放器之间切换。收藏和听单通过首页卡片进入。首页从收藏、听单和最近听书三种 Room 状态读取篇目数量、系列数量与断点。断点卡用正文各章的估算时长和已保存的播放位置绘制进度。顶栏收到 HTTPS 网址后复用 WebView 和正文提取器，成功后交给播放器。用户换页或切换标签会取消这次自动朗读。

应用进程的 ViewModel 持有章节与 ExoPlayer。用户选择起始段后，语音逐段合成，首段就绪时送入 ExoPlayer。当前会话的 WAV 片段写入一个私有缓存文件，Media3 按每个片段的字节范围读取。进度条以当前可播音频时长为准。预计总时长在首段就绪前按文本计算，随后按已生成音频校正，并在界面应用当前倍速。估算范围为当前页面已提取的内容。切换音色会从当前语音片段继续合成。Media3 MediaSessionService 与界面共享同一个 ExoPlayer，支持前台服务、系统媒体通知、音频焦点和耳机断开暂停。媒体通知返回播放器。用户开启混音后，播放器不请求独占音频焦点，听书音量可单独静音。应用检测电话或通信音频模式时暂停并写入进度。[Media3 后台播放文档](https://developer.android.com/media/media3/session/background-playback)

## 自动翻页

完成当前页的音频后，等待一秒再尝试同源 HTTPS 的明确下一页或下一章链接。已访问网址、相同正文与单次最多 20 次跨页跳转限制了重复和循环。手动导航会取消待执行的自动翻页。加载或提取失败时暂停并提示。

缺少明确链接时可点击网页里的可识别分页控件，随后等待同源页面正文稳定变化。支持用页码终止，正文按 SHA-256 去重，追加式分页去掉已经朗读的重叠段落。链接与模拟点击共用每次自动阅读链最多 21 页的限制。

睡眠定时由应用进程的播放器持有，后台播放时可继续计时。时间到前一秒渐降音量，再通过播放器的暂停和进度保存路径停止。「听完本章停」在自动翻页开始前暂停。

## 收藏与进度

Room 管理应用私有 SQLite 数据库。用户添加收藏后，保存正文快照、网址、章节、段落、片段偏移、播放位置、音色和倍速。播放时每两秒记录一次进度，并在暂停及跳转时记录。播放检查点写入独立的单条最近听书记录，同时更新已存在的正文收藏。Room v4 自动迁移添加网页图标和置顶字段。站点图标复用 WebView 加载的 favicon。删除文件夹时，在同一事务内将其收藏移回未分类。架构文件保存在 `app/schemas`。[Android Room 文档](https://developer.android.com/jetpack/androidx/releases/room)

Room v5 添加独立的听单篇目和游标。篇目保存顺序、正文快照与播放偏移，独立于收藏。最近听书与听单检查点在同一个事务中写入。Pixiv 系列按站点目录顺序添加，未提取的篇目首次播放时加载全文，落库之后复用快照。系列连读默认关闭，开启后使用作品详情的下一篇 ID，听单自身按用户排序自动播放。

Room v6 保存 Pixiv 系列目录、话数编号和收藏失败的作品 ID。收藏记录新增可选显示名和听完标记，进度写入保留已有显示名。界面用作品 ID 计算收藏与听单的加入状态。不同语言路径或跟踪参数指向同一作品时，应用复用已有记录。系列分组以目录编号排序，旧收藏可用正文快照里的系列信息分组。

## MCP

独立 Node.js 服务使用官方 MCP SDK 的 stdio 传输。Android 的 `mcp` 包通过 ADB 转发接收回环连接，使用每次启用时生成的令牌和三个独立权限组。删除收藏需要应用内确认。手机端复用真实 WebView、正文提取器、播放器及 Room DAO。授权与连接状态独立于应用内播放，详见[MCP 接入](mcp.md)。

应用包名为 `com.elainalisten`，最低支持 Android 8.0（API 26），编译和目标版本均为 Android 17（API 37）。WebView 使用网络连接，正文解析和 Matcha 合成在本地执行。选择 Azure 音色时访问 Azure Speech。系统备份关闭。
